Module resource model

A module is useful only when the evaluation path is clear.

For each platform, the goal is to show which development resources actually exist — not just the processor name.

01

Compute Module

The integrated compute platform and its real hardware status.

02

Carrier / DevKit

The fastest practical way to power up, connect peripherals and begin evaluation.

03

Software / BSP

OS, BSP, documentation and project access status for the exact platform.

04

Display / Demo

A matched display, touch and reference HMI path when available.

What do the platform statuses mean?
Exploring

Requirements are being collected; no development commitment is implied.

In Development

The module or platform resource is actively being developed.

Project Evaluation

A real platform can be discussed for suitable projects; exact configuration is confirmed case by case.

Production Ready

Used only after the specific module configuration, software and supply path are validated for production.
