Architecture options

Choose the software and compute class from the real workload.

A focused control UI, a graphics-rich real-time interface and an application-style Linux HMI have different engineering and lifecycle trade-offs.

Path 01

Compact RTOS HMI

For focused control panels where fast boot, deterministic behavior and compact software matter.

Path 02

Performance RTOS HMI

For richer graphics, more pages, charts or connectivity without moving directly to Linux.

Path 03

Embedded Linux HMI

For application-style workflows, networking, richer frameworks or broader software integration.

Hardware + software stack

Evaluate the complete HMI path.

01

Compute

MCU, MPU or SoC selected from UI complexity, interfaces and lifecycle.

02

Display & touch

TFT, touch technology and module integration matched to the operator environment.

03

Software

LVGL, Qt or another suitable GUI stack plus BSP, drivers and application integration.

04

Connectivity

Ethernet, Wi-Fi, Bluetooth, cellular or industrial interfaces as the product requires.

05

Memory & storage

DDR, flash or eMMC sized around OS, assets, data and update strategy.

06

Engineering

Architecture review, BSP, GUI integration, validation and production transfer when needed.
