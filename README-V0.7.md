# openhmi.network V0.7 — Curated Project Matching

This release strengthens the buyer-facing value of openhmi.network without adding a new marketplace layer.

## Positioning changes
- Keeps the Hero promise focused on moving an HMI project forward.
- Adds a curation statement: project requirements drive selection; the site is not a directory of parts or developers.
- Reframes the existing project-path section as **Filter → Match → Validate**.
- Clarifies that build resources are combined around project requirements, not offered as isolated components.

## Selection logic
- Hardware: adds decision criteria before component selection.
- Modules: explains when module-level integration is preferable to chip-level design.
- Software: explains when LVGL/RTOS vs Qt/QML/Linux is likely to fit and how engineering support is added.
- Developer Resources: shifts from collection-first to architecture-first resource selection.

## Expertise / contributor flow
- Contributor work remains public capability proof.
- Project CTAs now route through **Request Relevant Expertise** / **Discuss a Similar Project**.
- External LinkedIn links remain attribution paths, not the primary project CTA.
- No contributor tiering, partner marketplace, membership system or new partner map was added.

## Deployment
Use the direct upgrade ZIP to overwrite the repository root. The full ZIP is a complete V0.7 backup.
